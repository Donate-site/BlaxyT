# Сервер BlaxyT

Python 3.11+, стандартная библиотека. Основная точка входа — `shop.py`. HTTP-служба связывает профили по стабильному TikTok UID и обслуживает значки, импорт публичных каталогов, голосовые комментарии и метаданные обновления. Telegram-бот использует long polling; публичный webhook для него не обязателен.

1. Создайте отдельного бота и отдельную папку состояния.
2. Возьмите названия переменных из `.env.example`, задайте свой `TELEGRAM_BOT_TOKEN`, адрес HTTPS, путь `SHOP_DB`, контакт поддержки и свободный порт. Не публикуйте заполненный файл окружения. `shop.py` читает переменные окружения, а не загружает `.env` автоматически.
3. Скопируйте изображения из `badge-seed-images/` в папку `badge-images/` рядом с собственной базой (не заменяйте существующие файлы без проверки). Запустите `python shop.py` с подготовленным окружением. На Linux можно адаптировать `blaxyt-shop.service`: создайте пользователя службы и разместите код и файл окружения по указанным в нём путям.
4. Настройте HTTPS-прокси к службе в своей инфраструктуре. Не открывайте администраторские операции и базу данных наружу. Проверьте пути API в `shop.py` и согласуйте их с клиентом.
5. Продажи выключены, пока `SALES_ENABLED` не равно `true`. Значение цены в примере — 15 Stars. Сначала проверьте привязку и обработку оплаты/возврата на собственной тестовой конфигурации.

`grant.py` и `refund.py` — локальные инструменты оператора сервера. Запускайте их только с доступом к своей базе и окружению. Администраторские UID текущего проекта в коде необходимо заменить на свои и проверить авторизацию. Импортированные значки сохраняют источник; каталог публичных сторонних значков не является списком покупателей BlaxyT.

В эту публикацию не включены базы, голоса пользователей, токены, ключи SSH и сценарии доступа к рабочему серверу. Скрипты `verify_*.py` служат для изолированных локальных проверок — прочитайте используемые ими пути и переменные перед запуском.
